## Authority, action and boundaries

The authority remains PRODUCT_GOAL → DEVELOPMENT_PLAN → the original journeys/ACs → traceability → ADR → failures. The new scientific-UX requirement supplements quality constraints; it does not change the eight researcher workflows or replace scientific validation with attractive screens.

- F10: P02/P04, J02/J04, AC-J02/AC-J04. A researcher names a parent and source map, compares an explicitly supplied reference, stages exact substitutions, inspects parent/child differences, and saves a new child plus coordinate-bearing Lineage.
- F11: P02/P03/P04/P06, J02/J03/J04/J06 and their ACs. A researcher retains a proposed explanation/question, limitations and next experiment with actual molecule/Evidence/Lineage/residue/Structure/model references. This can target an existing candidate without making a child.

Inputs are existing immutable Molecules, imported ResidueMaps, original Evidence, declared compositions and Structures. Outputs are new Molecule/Lineage records and a distinct proposed Hypothesis. Parent records remain unchanged. Preview writes nothing; save/import revalidates all actual references and atomically persists the complete reviewed records.

This directly advances the original P02 question and the shared P03/P04 reasoning gap. It is required M3 work, so a discretionary feature score is not substituted for the mandatory identity, provenance, security and regression gates. Automatic humanization, new numbering/prediction engines, humanness scoring, indels, interactive assembly, construct comparisons and finalized decisions remain outside this action.

## Scientific identity and provenance assessment

**Exact edit identity: design PASS.** Parent molecule + actual chain + explicit map/domain + scheme + integer coordinate + exact insertion string resolves to a real raw index and recorded original residue. Neither a client offset nor the first/latest map authorizes an edit. Unsupported target symbols remain unsupported rather than being interpreted as different residues. Duplicate/no-op/empty changes reject.

The initially ambiguous ADR phrase about partial coordinates was corrected during review. An eligible mapped partial domain may authorize an actually observed position; absent positions, unavailable/failed/unverified maps cannot. Full CDR completeness is a separate property. Raw-index, map-coordinate and structure-author-number identities remain distinct.

**Reference comparison: design PASS.** Both explicit map identities and their sources remain visible. Same scheme, domain definition and chain type are required for the planned coordinate comparison; gaps remain unavailable. A researcher-supplied human reference is not a sequence-derived species classification. The interface must label this as comparison of recorded coordinates, not a newly calculated alignment or an assertion of homology. IMGT explicitly qualifies its CDR coordinate-comparison statement by equal CDR length; unequal observed region lengths, gaps and incomplete coverage must therefore remain visible. No child's numbering, region confidence or function is attested by its parent's map. [IMGT unique numbering](https://www.imgt.org/IMGTScientificChart/Numbering/IMGTnumbering.html)

**Child and component provenance: design PASS.** The child is a distinct molecule and receives no parent Construct, Material, Evidence, Structure, correspondence or verified map through inheritance. Parent-region labels in D are explicitly scoped to the parent source. A changed component cannot retain an exact BindingUnit interval whose sequence it no longer equals. Setting that changed child's direct interval origin to null preserves the existing meaning of an exact origin, while complete parent/child composition signatures and coordinate-bearing Lineage retain actual ancestry. Unmodified origins, connections, component order and declared copy counts remain intact. All copies of an edited chain definition are affected and disclosed; copy-specific physical editing is not claimed. No existing parent ancestry is deleted or rewritten.

**Hypothesis semantics: design PASS.** A Hypothesis is an immutable `proposed` record, separate from measured/computed/literature/annotation Evidence and Decision. Sources, time and actual local-entry mechanism are recorded without inventing an authenticated author or validation. Original Evidence stays on its own direct subject. Related molecules must include each Evidence's actual owner and both ends of referenced Lineage. Residue references resolve on the named chain/index; structure, model and correspondence references must be mutually consistent. Unknown/file-level model scope remains explicit rather than becoming model 1. Proposed text does not generate scientific confidence or establish causal truth.

## Independently proposed required edge cases

1. **Overlapping map aliases and insertions.** Two eligible maps on the same chain resolve requested edits to the same actual raw residue. Reject duplicate edits across map IDs, even if their coordinate labels differ. At the same time, allow distinct physical H/L or domain positions with identical coordinate labels. Keep 111, 111.1 and 111.10 exact and separate; never use float or lexical aliasing. If the selected coordinate is absent, report unavailable without using its nearest neighbour.
2. **Partial domain and unequal reference coverage.** An eligible partial parent map permits its actual observed residue but rejects a missing coordinate; an unverified map permits neither. A reference with a gap or unequal observed CDR length displays the limitation and supplies no replacement residue for the gap. Distinguish incomplete coverage from a verified biological deletion. A reference's species/verified status is never inferred from a title or matching sequence.
3. **Component boundary/copies/origin.** Edit the last residue of one component and the first of the next in a chain declared with two copies. Preview both affected component sequences and all copies; clear only origins that no longer match, preserve unrelated origin/connection/copy data, and retain exact parent signatures. A later reversion to an old sequence must not discover or restore an origin by sequence matching alone.
4. **Forged preview/import and atomic rejection.** Alter a reviewed child at an unlisted raw position, change an unrelated chain, retain an invalid changed-component origin, falsify from/to or map ownership, or omit a required new record. Full reconstruction must reject the entire import with the database and parent unchanged. An existing ID collision must not partially save the child, Lineage or Hypothesis.
5. **Hypothesis subject/model isolation.** Use a same-sequence candidate's Evidence, omit the actual parent from a child hypothesis, attach the wrong Lineage, or combine model-2 confidence/context with a model-1 correspondence. Reject inconsistent references while preserving truly unknown/file-level scope explicitly. No child measured value, construct, structure or verified numbering is produced. Restart/export/reimport must preserve original text, IDs and context exactly.
6. **Draft/project switching and human operation.** Stage mutations or hypothesis text, then switch projects or selections before preview/save. Never apply the old draft to a new parent or leak unsubmitted scientific text/sequences into localStorage. Stale contexts reject visibly; preserve cross-screen selection IDs. Keyboard/mouse selection, source drill-down, removing a change, correction after an error and final before/after confirmation must work without colour alone conveying the mutation or provenance state.

The happy-path acceptance remains the actual named `e2e_j02_humanize_variant`: parent VH/VL, explicitly supplied human reference, exact map/FR/CDR/insertion observation, child and difference preview/save, retained reason/hypothesis/Evidence, actual process restart and exact exported data comparison. Both prescribed negatives, `e2e_j02_numbering_unavailable` and `e2e_j02_insertion_mapping`, must execute in the browser. Passing backend constructors alone cannot pass J02. Full J03/J04 require their own named complete paths; shared Hypothesis plumbing does not pass J06.

## Mission alignment and passage boundary

Mission alignment: **PASS**. The proposed work closes an identified break between observation and a retained research action. Its value is that a researcher can say exactly which residue was changed, why, what original evidence supports the proposal, and what remains to test. Dense scientific data, familiar selection/comparison interactions and progressive source detail serve that action. Tool counts, test counts and visual polish do not establish usefulness, scientific correctness or experimental success.

The largest next risk is expanding several generic editors or controls before one complete parent/reference → numbered child → original evidence → proposed question is usable. Keep F10 and F11 reviewable as connected actions; complete their actual cross-screen path before interactive assembly and later M4 comparisons. Do not undertake the possible E statistics-card cleanup until a relevant E task demonstrates the need. Actual researcher evaluation and human scientific golden validation remain open.

Identity/provenance/security/regression design gates are compatible with the existing contracts. Approval is to implement and independently verify this design, not to integrate unreviewed domain code. No changed mission, external-sharing default, molecular identity equivalence or new scientific definition is authorized.

M3 development necessarily changes the source inventory from J01's accepted revision. Preserve the historical J01 result and tested source evidence. Do not describe it as current-source acceptance while hashes differ, rewrite its old manifest, or delete tests to silence the mismatch. At the F10/F11 milestone, run the existing J01/foundation/numbering/structure paths plus new design/hypothesis cases, obtain an independent implementation verdict, and register current acceptance from fresh exact-source evidence.
