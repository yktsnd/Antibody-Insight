## Cause and bounded interpretation

The server's strict JSON parser/preview preserves Python integer/float distinctions and signed float zero. The browser parses the response for UI use, then `api()` applies `JSON.stringify` again when committing the approved bundle. Export likewise parses a fresh server bundle and stringifies it for the download. Integral floats and negative zero lose their recorded representation/type along those browser paths.

This does not show that1 and1.0 are different physical quantities or that an actual experiment's measured magnitude changed. It does break the application's existing type-aware recorded-context policy (`observation.context_key`) and exact record roundtrip contract: groups deliberately kept separate by the server merge after transport. Existing JavaScript equality checks can mask that failure. Previously accepted journey reports remain historical evidence for their tested fixtures; they do not establish this newly exercised boundary.

## Minimal correction assessment

Preserving authoritative server JSON for unchanged approved bundles is appropriate: keep the raw root response in a volatile WeakMap, and supply a serialized bundle string alongside nested preview envelopes. Parse normally for display; import/export use the matching raw snapshot. This needs no custom numeric parser, library, persisted snapshot, server preview cache or new external operation. Existing server validation, session/Origin/CSRF and source/draft ownership must remain intact.

The raw snapshot must be associated only with the actual server root/wrapper bundle, with a matching client fingerprint. A stale raw body must not ignore client changes. For a *known snapshot changed after review*, rejecting it and requiring another server preview is the simplest way to preserve untouched typed fields as well. Falling back to ordinary stringification for that changed snapshot can normalize unedited float metadata again, and strict server validation cannot detect a valid-but-normalized value. Unknown/plain direct request objects may retain the existing explicitly supplied JSON path and strict server checks. Do not recursively trust user-supplied fields as transport companions or place scientific snapshots in localStorage.

Acceptance requires the retained real-browser regression to preserve every typed canonical record, nested signed zero and both contexts through preview/save/export/fresh reimport, plus explicit mutated-snapshot/body ownership tests. No final fix PASS or M4/J06/J08 completion is claimed by this investigation.
