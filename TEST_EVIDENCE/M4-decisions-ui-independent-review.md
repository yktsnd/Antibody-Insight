## Independently added boundaries

1. **Delayed context/readout and exact source choices.** While the context request is held, newly entered private reason and chosen subset survive its arrival. Empty weight/preference remain empty rather than defaulting to0 or an objective. No sole observation is selected automatically. Separately seeded computed, different-unit and integer-versus-float-condition contexts remain separate from the actual measured context; incompatible Evidence IDs do not enter its choices. Selecting real zero retains the actual subject UUID/lot and original unit. Typed-condition separation is the existing recorded-context policy, not a claim that numeric spelling changes a physical condition.
2. **Edited/project-scoped preview ownership.** A response to an earlier reason cannot open its modal after the reason changes. A response from the original project cannot replace a newer project's reason or open a stale review there. Actual persisted data stays unchanged; a fresh preview uses the edited reason.
3. **Rejected old save versus new pending save.** After the first submission's modal is closed and a new reviewed draft is submitted, the older rejected response cannot enable the newer Save button, insert its obsolete error or save the old draft. Releasing the current submission saves only the current approved Decision.
4. **Successful old save versus another project.** A submission may finish in its actual original project after the researcher moves to another project. It does not navigate back, clear the new private reason, change that project's records or rebind the original record. The current project and draft remain intact.
5. **Actual legacy continuation and stale head.** The real old-format shortlist stays visibly a draft and retains its exact original fields. Continuing it through the actual UI saves a separately identified draft revision2 without adding fields to the old record. A later UI revision3 preview becomes stale when another authenticated local request saves its own genuine server-reviewed successor. Saving the stale preview rejects atomically; exactly one successor exists and no old record changes. After reload, the advanced predecessor's revision action is disabled. Inspecting the competing saved record is read-only and explicitly labelled `Frozen draft revision 3`, with no Save action. The competing request is a synthetic second client used only to create the real concurrency condition; it does not call application callbacks or bypass server validation.
6. **Selection-scope ownership.** A delayed three-candidate review cannot reopen after the researcher creates a separate two-candidate question. Both scopes retain their own unsaved reason; returning to the original three candidates restores that draft. No write occurs in this rejected-preview path.

All six groups conclude with no private reason, criterion source content, metric/conditions or choice payload in localStorage; no JavaScript errors or outbound browser requests were observed. The gate interceptor is limited to the actual local origin so the separate outbound-request recorder continues to cover external requests.
