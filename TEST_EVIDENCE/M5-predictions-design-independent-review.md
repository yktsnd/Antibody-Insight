## Independent primary-source check

The [official AlphaFold 3 output specification](https://github.com/google-deepmind/alphafold3/blob/main/docs/output.md), independently read on 2026-11-04, distinguishes sample summaries from detailed arrays. It defines ptm, iptm and fraction_disordered on [0,1], and ranking_score on [-100,1.5]. Ranking is for structures; it is not affinity. Atom, token, chain and chain-pair outputs have distinct scopes. The proposed scalar extraction preserves those boundaries. Native null acceptance is an application missing-data rule, not a claim that every official producer emits null.

The [Galaxy history tutorial](https://training.galaxyproject.org/training-material/topics/galaxy-interface/tutorials/history/tutorial.html) independently confirms source-dataset history navigation and complete-history export/import. The [official introduction](https://training.galaxyproject.org/training-material/topics/introduction/tutorials/introduction/slides.html) describes per-dataset tool/version/input/parameter metadata. This supports progressive source disclosure and reusing complete-project transport. These are documentation benchmarks, not hands-on usability or integration/licensing approval. No private input was transmitted; only public documentation was fetched.

## Design fit and bounded implementation interpretations

1. **Source entity is justified.** Current F16 import_origin stores a row reference, digest and importer attestation; it does not retain original CSV text. A Structure contains coordinate-specific identity, format, origin and parsing constraints. Neither should be repurposed into a prediction source. A single prediction_file plus scalar pointers avoids copying an arbitrarily large source into every Evidence. Reuse generic append-only storage, validation and full awx export; do not introduce a general attachment store, archive format, workflow system or retrospective F16 migration.
2. **Strict schemas and row exclusion have different boundaries.** Enumerate all unknown canonical schema-field pointers across root, records and source objects before rejecting the whole file; do not report only the first validator failure or save known siblings while dropping unknown fields. Arbitrary documented conditions metadata is data, not an unknown schema field. Only a structurally supported file may exclude invalid known-schema records through explicit row/pointer QC and a reviewed valid subset. A native summary is one source record: malformed recognized scalars must fail that summary rather than being silently ignored while another scalar saves. Unsupported native content is retained verbatim and listed by exact path; a retained subtree can be listed once without enumerating every array element, provided that its unsupported descendants remain inspectable. No supported scalar means no source-only save.
3. **Source identity is an assertion, not authentication.** An actual positive coordinate model ID must exist in the explicitly selected computed Structure. That model ID is not an external AF3 seed/sample/run identifier. Explicit linking records the user's assertion; neither matching filenames nor a shared model number proves two files came from one run. Show the actual coordinate file/hash/model, prediction file/hash and any actually provided external identifiers together. Do not infer absent external identifiers or a computation time. Original event time and tool version/null remain distinct from import time/importer version. Conditions must not overwrite reserved selected-model metadata; a conflict rejects.
4. **Exact references remain exact.** Canonical direct Molecule/Construct/Material/Structure IDs stay distinct and same-project; opaque tokens require explicit file-bound mappings. Recognized application-ID prefixes must not become a route for redirecting missing, foreign, wrong-type or malformed application IDs. No name, case, whitespace, UUID-normalization or sequence fallback. Native targets require computed structures; canonical generic computed results must still retain their explicitly declared direct subject and scientific scope. No mutation inherits parent measurements or prediction sources.
5. **Origin consistency belongs in graph validation.** Validate source hash, format, bindings/options, actual subject/model, pointer, value and typed context on every direct awx import too. Numeric equality alone is insufficient: bool is not int, 1 is not 1.0 for retained recorded types, and signed zero must survive transport. A forged pointer or a changed source/conditions/version/description/residue scope must fail even if the displayed number matches. Dependencies must be validated independent of entity order. Old Evidence without the optional origin and old Decisions remain byte/shape compatible and are not enriched retrospectively.
6. **Size and safe display are part of replay.** Retain exact submitted UTF-8 text, including BOM/newlines, and hash that text; never hash a reserialized object in its place. Reject undecodable bytes, duplicate keys, unsafe/nonfinite numbers and oversized input without truncation. Bound both individual source size and complete JSON-escaped project request size: a source that saves but cannot be reimported under the existing 32MiB body ceiling does not satisfy J08. A size check on the unescaped source alone is insufficient. Render raw text/filenames/tokens as escaped text, never executable HTML, URLs or local paths. Keep raw files/mappings/drafts out of localStorage and external requests. Parse each source once per validation operation where practical, rather than once per extracted scalar.

These are bounded implementation clarifications consistent with the ADR and original requirements. They do not require a fundamental requester decision. A change to identity/provenance semantics, interpretation of unsupported scientific arrays, external sharing or the eight original journeys would require escalation under AGENTS. This PASS does not authorize such a change.

## Required replay and independent extra edges

Happy path: use clearly labelled fixture files through the actual FASTA, structure, measured CSV, canonical and native prediction controls. Explicitly select known direct subjects and a computed structure/model; retain null, zero, typed conditions and unsupported native content. Inspect actual source/model/chain mapping in W and source kinds/time/version/Material in R. Include Lineage, proposed Hypothesis, finalized Decision and an independent revision. Restart; export through the native control; file-import into a genuinely fresh database. Compare canonical typed data, all IDs/kinds, source text/hashes, mappings, dependency closure and fixed decision history. Existing raw structure and new prediction content must match exactly. Existing FASTA/CSV provenance must retain its actual recorded scope; do not falsely claim retained raw FASTA/CSV bytes where the existing adapter stores only derived records/digests.

Original negatives remain mandatory: duplicate IDs reject atomically without overwrite; a broken structure cannot damage previously stored data. J03 unmappable-residue and missing-confidence behavior, all seven accepted journeys and all fourteen accepted prescribed negatives must remain intact.

Independent additional edge cases proposed here:

- **Same model number, different samples:** two computed structures both have model1 and identical sequence/name, with two different prediction files. Link each explicitly; then switch the selected structure or source during an in-flight preview and at save. Reject stale ownership; never move or display one sample's metrics on the other. An unknown coordinate model must not become model1.
- **Escaped source paths and hostile tokens:** use opaque references containing `/`, `~`, Unicode, `__proto__` and HTML-like text, plus an unsupported nested field with escaped keys. Require exact mapping, correct JSON-pointer escaping, complete unsupported-path reporting, safe display and identical raw text on fresh replay. No prototype/property lookup may establish identity.
- **Typed equal-looking tampering:** direct awx import changes a source-backed condition 25.0 to25, value -0.0 to0.0, null to0, or numeric1 totrue while leaving origin/hash otherwise unchanged. Require rejection with no partial writes and unchanged finalized decisions. Also test a different pointer whose value happens to be numerically equal.
- **Valid subset and hidden unknown fields:** several known-schema rows contain one invalid subject and a later nested unknown field. The full unknown-field scan must reject the whole file; removing that unknown field allows reviewed row exclusion. A native true/array scalar must not disappear into the unmapped list merely because another recognized scalar is valid.
- **Transport amplification:** a near-limit valid source with escaped quotes/newlines expands in full awx JSON. Preview/save/export/fresh reimport must either all fit the documented envelope or reject before persistence; no source truncation, half import or unrecoverable accepted dataset.

## Mandatory gates and acceptance boundary

| Gate | Design finding | Later evidence required |
|---|---|---|
| Identity | PASS for exact typed bindings, actual source-model selection and explicit assertions | Wrong/foreign/reserved/stale mappings, source/sample swap and full-ID replay |
| Provenance/scientific meaning | PASS for computed-only origins, raw preservation, no fake output and source-defined scalar scope | Direct awx forgery rejection, typed origin consistency, W/R source inspection and frozen history |
| Security | PASS for local-only design and reuse of session/Origin/CSRF/atomic storage | Hostile content, no private draft localStorage/outbound requests, limits and rollback |
| Regression | PASS as a compatible extension plan; no regression result inferred | Actual retained J01-J07 +14 negatives and legacy exact-data continuation |

Prefer the proposed narrow native summary plus canonical contract over either a generic ETL/array engine or forcing every researcher to manually rewrite a common scalar summary. The existing native preview, selectors, source detail, append-only entities and complete-project export are sufficient building blocks. Full J08 and the new domain change remain **implementation and independent verification pending**. Only the later independently replayed implementation can qualify for integration.
