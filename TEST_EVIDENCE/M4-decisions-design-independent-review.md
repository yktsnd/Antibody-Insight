## Clarifications resolved before design approval

1. **Legacy versus new record boundary: resolved.** The revised ADR identifies legacy only when all three new fields (`chosen_candidate_ids`, `source`, `hypothesis_ids`) are absent and the exact original empty-criteria/draft/revision1/no-predecessor contract holds. Any new-field presence or nonempty criteria enters complete new-shape validation; malformed new records cannot evade gates. New drafts may have empty criteria/chosen subsets but retain a nonempty reason; each present criterion is otherwise fully defined. A new revision may reference an actual legacy shortlist without altering that old record. This preserves existing data and J01 behavior. Older applications may reject unfamiliar fields; this approval is preservation of old records by the new implementation, not compatibility of new records with old binaries.

2. **Anchor eligibility and draft missingness: resolved.** Every saved numeric criterion anchor must pass existing `context_issue`; the candidate-choice key set exactly equals the comparison candidate set. Choices are null or eligible same-context originals resolving to that candidate. A selected Evidence whose scalar is null remains selected and is reported as value-missing. An unselected choice remains null even when one source exists; several options remain an unresolved choice. No implicit single-record selection is inherited from `observation_order`. Incompatible, foreign, out-of-scope, unknown or stale IDs reject even a draft. Missing criterion/choice/scalar and an unchosen subset are supported draft incompleteness; malformed scientific metadata is not. Incomplete-context original records stay available in source cards without manufacturing a compatible context.

3. **Requirement/scope changes: resolved.** The revised ADR explicitly requires researcher action/reason in a saved version and visible differences for changing the required predicate or comparison scope. This includes required→optional and removal of an incomplete candidate. Existing snapshots remain unchanged. All draft/final successors use one atomic single-successor rule, and direct JSON import must revalidate the same contract as UI preview/save. The ADR also distinguishes saved version changes from unauthenticated, volatile keystrokes; no exhaustive edit audit is claimed.

The initial review was NEEDS-EVIDENCE for these bounded ambiguities. The implementation agent revised ADR-0010, and this reviewer independently reread the complete revision, including its new validation-boundary section, before issuing this PASS. These are implementation-contract clarifications within the original action, not a change to mission or scientific policy; no requester escalation is needed. Implementation, browser replay, persistence/security/regression evidence and independent implementation PASS remain required before integration. Full M4 remains unfinished.

## Required-missing policy and scientific meaning

The original AC requires visible missing required criteria and controlled finalization; it does not define whether a required criterion applies to chosen candidates only or all comparison candidates. **The proposed all-comparison-candidates predicate is acceptable** as an explicit conservative readiness policy: for each required criterion, every compared candidate must have an explicitly selected, eligible, non-null numeric observation. An unchosen candidate's missing value still blocks finalization. Label this as the application's declared decision-completeness policy, never as a scientific theorem or proof that the evidence is comparable.

Researchers may explicitly revise the required flag or comparison scope with the visible difference/reason above. A chosen-only predicate could permit a justified rejection of incomplete candidates, but would need a separately specified policy and could conceal incomplete comparison; it is unnecessary for this bounded J07 implementation. A generic waiver engine would increase effort without serving the original action better.

Weights are declared importance only. Zero weight is valid and does not disable a separately required criterion; negative/nonfinite/boolean weights reject. No sum-to-one or positive-total constraint is scientifically necessary when no composite is computed. `higher`/`lower`/`inspect` is an explicitly authored interpretation aid. Metric/units/kind/conditions/source are derived from the original anchor; changing them cannot relabel an incompatible observation. `inspect` does not turn an unknown numeric scalar into a satisfied required cell. All-optional criteria may remain incomplete if the researcher explicitly chooses and explains a final decision; the application must show that incompleteness without inventing evidence.

The numeric-only comparison subset is sufficient for the original binding/property/expression engineering action, provided literature/annotations and proposed hypotheses remain visible and citable. It is not acceptance of every future qualitative decision workflow. A real researcher who cannot express an essential trade-off is evidence for revisiting the boundary, not a reason to add a scoring model now.

## Compatibility and implementation gaps found independently

- `domain.py` currently permits only draft revision1/no-predecessor Decisions with empty criteria. Its strict field list rejects all proposed additional fields. New shape/reference checks must explicitly preserve that legacy branch. Existing `shortlist()` remains the J01 behavior and must not be reinterpreted as finalized research selection.
- Existing `molecule_id_for()` resolves Material→Construct→Molecule and direct Construct/Structure/Molecule scope without equal-sequence inference. Reuse that rule for each criterion choice and supporting snapshot. A table row is a molecule-level comparison view, never a reassignment of a Material's measurement to that molecule or its siblings.
- `observation.py` provides strict typed context equality and rejects missing assay/source version/unit. Its `observation_order()` automatically selects a sole eligible observation and sorts rows; blindly reusing it would violate the proposed explicit-choice contract and could suggest ranking. Reuse `context_issue`/`context_key` and explicit source options without inheriting implicit selection or automatic criterion ranking.
- `domain.validate_graph()` already enforces complete original Evidence snapshot equality using canonical JSON, including int/float distinctions and signed zero, unique snapshot IDs and candidate scope. Extend the required snapshot union to include anchors, every non-null choice, additional supports and all related Evidence of referenced hypotheses. The union must contain those required records even if a client omitted one. Never rebuild snapshots from labels or rounded browser values.
- `storage.py` already has append-only database triggers and `BEGIN IMMEDIATE` around import. Put predecessor, exact revision increment and single-successor checks in validation of the entire combined graph within that transaction. Validation must be independent of entity input order; reject cycles, multiple successors within one imported bundle and stale successors racing across separate requests atomically. A valid latest draft/final successor must never mutate its predecessor.
- `hypotheses.py` validates explicit molecule scope, related Evidence, lineage and residue/structure identity. Referencing an immutable proposed hypothesis is sufficient without copying it into a second narrative field; require its entire scope within the comparison and preserve its ID and related Evidence union. Existing append-only entities and full project export preserve the original hypothesis object. Do not promote its status to a fact or validated result.
- Existing full-bundle export can carry predecessors, actual subjects and hypothesis dependencies. The new import validator must accept a complete historical chain in arbitrary entity order and reject ID collisions unchanged. Export/reimport and actual restart must verify exact stored values, not only a rendered table.

## Independent acceptance replay proposed

**Happy path:** three clearly labeled synthetic molecules each have original binding/property/expression records, including repeated measurements and at least one optional missing scalar. Choose every source explicitly, author three criteria and importance values, inspect the exact original Material/lot in W, return to the intact R draft, save a draft, revise one weight with a reason, finalize a chosen subset, export/restart/fresh reimport, and create a successor to the finalized record. Verify exact IDs, criteria/weights, values, typed conditions, source versions, source/decision timestamps, proposed-hypothesis references and immutable earlier snapshots. Browser selection context and volatile draft ownership must survive the W/R path.

**Original negative 1:** A and B have the required expression observation; unchosen C lacks it. Finalization rejects atomically, identifies C/criterion and does not use zero or the selected candidates alone. Saving a missing-data draft succeeds. Requirement/scope changes appear explicitly in the saved revision and reason.

**Original negative 2:** add a later Evidence record after finalization and attempt a stale successor. The old record and exact snapshot remain byte-equivalent in canonical persisted JSON; only a valid new ID/revision may incorporate the later observation. Stale save leaves the database unchanged.

Additional reviewer-proposed edges:

1. **Unique source is not consent; null source is not absence.** A candidate has exactly one compatible source and it has numeric zero, another has a selected null-valued source, and a third has multiple same-context sources from different lots. Omitted choices remain null; an explicit zero satisfies presence, an explicit null does not, and alternatives remain independent original records.
2. **Snapshot dependency closure across hypotheses.** A selected hypothesis spans A and B, cites an Evidence not displayed as a numeric criterion, and has an exact structural/model/residue reference. Its related Evidence must be frozen even when omitted by the client. Adding C outside the comparison to that hypothesis scope rejects; no partial hypothesis copying or neighboring structural fallback is allowed.
3. **Imported fork in reverse order.** Import a valid root and two distinct revision2 successors in the same bundle, ordering successors before the root. Reject the whole bundle. A linear root→revision2→revision3 in reverse order succeeds. Repeat a stale successor against an existing latest revision; neither branch overwrites an earlier record.
4. **Typed and provenance incompatibility.** Identical labels/values with measured vs computed kind, `25` vs `25.0` vs `true` condition metadata, differing units/source version or equal-sequence but different molecule IDs cannot satisfy each other's context/subject choices. Exact snapshots preserve negative zero through approved transport; no conversion is introduced.
5. **Required zero importance and optional no evidence.** A required criterion with weight0 still blocks on a missing cell. Three optional criteria with null choices may be finalized only with an explicit chosen subset and reason, and the exported record still displays missingness rather than a fabricated result.
6. **Draft compatibility and stale navigation.** A legacy empty-criteria draft reimports unchanged. A partial new record is rejected rather than treated as legacy. While a source inspection/preview is pending, change project/candidate/revision; the older response cannot replace the current draft, preview or accepted save, and no scientific text/values enter localStorage or outbound network requests.

## Product alignment and mandatory gates

This action remains coherent with E/W/D/R and directly addresses P07 while reusing evidence/source/hypothesis work from P01–P06. Native criteria tables, source choices, a plain reason and immutable versions are simpler than an optimizer, notebook framework, global dashboard or custom visualization. The largest product gap remains the unimplemented complete J07 action, followed by full J08 reproducibility and scientific/user/release validation. Engineering fixture counts cannot establish scientific utility.

Identity: appropriate proposed direct-subject rules; implementation checks pending. Provenance: appropriate exact snapshots/version chain; closure and new-shape checks pending. Security: no new external transmission/persistence mode proposed; existing session/Origin/CSRF, safe rendering, localStorage and async ownership protections require focused regression. Regression: existing legacy records/J01 and accepted J02–J06 must remain intact; not executed in this design review. Therefore no integration or milestone-complete claim is made.
