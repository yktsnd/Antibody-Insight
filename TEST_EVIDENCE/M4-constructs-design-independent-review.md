## Scientific and provenance constraints accepted before implementation

- **Actual subject identity:** a canonical application ID is reserved and cannot be redirected as an external alias. A known same-project Material resolves only to itself; wrong-type, unavailable and foreign canonical IDs reject. Only genuinely external reference tokens receive explicit mapping to a real same-project Material. No name/lot/sequence matching, UUID/case/whitespace normalization or first-choice fallback establishes identity. Mapping must display the actual Material→Construct→Molecule path.
- **Sources remain distinct:** row source name/version are a pair; an absent row version remains null and must not borrow the file-level version of another source. Import file/row/hash/mapping and actual importer/version belong in import provenance, not assay conditions or the experimental tool version. This keeps row provenance from splitting or manufacturing scientific comparison contexts. The CSV adapter computes the submitted UTF-8 text hash; imported JSON provenance is a recorded attestation, not authenticated verification of an absent original file or arbitrary original encoding.
- **Unknowns and qualifiers:** null is not zero. Event time comes from the supplied observation, not the current import time. Units, typed conditions and unknown source versions remain explicit. Censored/qualified tokens such as `<0.1`, `>100` and `ND` cannot become threshold point estimates or zero; reject them as unsupported point values. Explicit curation may retain the original qualification in description with a null scalar. Equal rows/hashes do not prove identity or independent biological replication.
- **Construct interpretation:** local registration provenance names an actual entry mechanism/application version, not an authenticated author or inherited experimental source. The recorded Molecule association does not validate CDS translation or a multichain CDS/chain correspondence. If either CDS is null, including two nulls, comparison is unavailable rather than identical. Raw DNA indexes remain separate from amino-acid or aligned coordinates. No synonymy, signal processing or expression causality is inferred.
- **Persistence and partial import:** preview exact valid/excluded rows and unresolved/unsupported fields; save only an explicitly reviewed subset through existing atomic validation. Recheck references at save time. Keep repeated observations and Materials as separate rows, preserve old optional-field absence and frozen snapshots, and never create measurements when registering metadata. Missing conditions/units/version cannot silently join a known context. No pooling, unit conversion or automatic mean is proposed.

The parent acknowledged these refinements and they are recorded in ADR-0009. They clarify implementation boundaries within the existing mission and scientific identity model; no unresolved product-purpose, licensing or confidentiality choice requires requester approval.

## Independently proposed implementation edges

1. **Identity ambiguity:** two Materials have the same name/lot but different Construct IDs; one CSV token is an actual Material ID, another is an opaque lab reference. Attempt a conflicting mapping for the real ID, a known Construct/Molecule ID, and a foreign canonical Material ID. Each must reject or remain unresolved without changing the original subject; the opaque token maps only through the chosen actual ID. Include prototype-like tokens such as `__proto__` in the explicit mapping path without object-property side effects.
2. **Source/value/context boundaries:** mix per-row source names with blank versions while file-level source/version are supplied; the row must not inherit the other source's version. Test null/zero, unsafe numbers and underflow, qualified values, typed JSON conditions, unlike units and unknown conditions. Keep separate observation rows and source metadata; do not label equal records as independent replicates.
3. **File/project/draft ownership:** hold reference analysis, preview or save while changing CSV bytes, file name, mappings, target project, selected Construct/Material or a newer draft. Old callbacks must not reuse stale mappings, clear newer input, navigate to the old saved project, inject an old error into a newer review or unlock its in-flight button. Audit the current generic import callback when extending it: it currently clears global pending-import state and refreshes the saved project after completion. This is an implementation test requirement derived from source inspection, not a claim that a new reproducer was executed here.
4. **Legacy/provenance/restart:** old Construct/Material/Evidence records without the new optional fields must remain unchanged through save/restart/export/reimport. Malformed import provenance, Boolean/float row indexes, invalid digest shapes, wrong references and unknown fields reject atomically. Changing a stored snapshot's provenance must fail. Show both-null CDS as unavailable and preserve the actual two Construct/three Material identities and next experiment after restart.
