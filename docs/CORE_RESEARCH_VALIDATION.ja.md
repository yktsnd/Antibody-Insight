# 実在抗体を用いる中核研究体験の検証

[English](CORE_RESEARCH_VALIDATION.md) · [開発順序](../DEVELOPMENT_PLAN.md) · [現在の不足](../KNOWN_LIMITATIONS.md)

確認する問いは、候補間の違いがどの分子・残基・試料・測定条件に由来するかを説明し、根拠のある変異案、次の実験、選定理由を別の研究者に渡せるか、である。

合成例は操作を確認するためのものとし、通常のファイルから実資料を登録する試験を別に行う。公開実験構造1MLCにはFab D44.1の配列と座標が含まれるが、実際の試料の同一性、測定値、人が照合したIMGT番号対応を代用しない。不足する資料を架空の記録で埋めない。

1. 通常のFASTAを開き、レコードごとに候補ID、鎖ID、役割を明示する。全鎖の配列と宣言した分子形式を確認して保存する。従来のFASTA取込では別候補になることも確認する。ファイル名・ハッシュ・元のレコードと行番号を残す。
2. 実際のPDB/mmCIFを対象候補に登録し、原資料に基づく鎖・残基対応を用いる。同一残基の連続、欠損座標、挿入コード、代替配座を独立に照合する。ポリマー内の順序が一致しても、アラインメントの正しさが保証されるわけではない。
3. 原資料があるコンストラクトと試料を来歴付きで登録する。実測CSVには実際の測定日時、単位、条件、出典を記録し、試料を明示的に対応付ける。資料がなければ、この段階は未達とする。
4. 試料と条件を区別して元の観測値を比較する。欠測と比較可能性の限界を示し、違いについて何が言えるかを説明してから、実験や変異案を選ぶ。
5. 実際の配列に対し、出典・版が明らかで、人が照合した番号対応を用意する。W/Dで対象位置と参照を確認し、理由と子候補の系譜を保存する。親の実測・番号対応・構造を子の観測として継承しない。
6. 提案段階の仮説と次の対照実験、選定理由と正確な根拠を保存する。別の担当者が「なぜ残したか」「次に何を測るか」を再構成できるか確認する。再起動と空の保存領域への再取込でも同じ対象と根拠を保持する。

各段階で、入力資料、保存ID、操作記録、科学的な問いに答えられたか、外部ツールへの戻り、IDの再入力、根拠の探し直し、文脈の中断を記録する。研究者の従来の方法と所要時間を比較し、クリックが成功したことだけで改善を推定しない。実装、独立した工学的検証、人手による科学的照合、説明を受けない研究者の利用評価を分ける。

現在は、合成例と、公開配列の通常FASTAからH/Lを明示して登録する範囲を独立に検証した段階である。上記の実データ経路全体、科学的妥当性、8役割にとっての有用性は未検証。次の実装は、この経路で実際に確認した最初の障害を優先する。

[独立した実現可能性レビュー](../TEST_EVIDENCE/M6-real-core-independent-gap-review.md)では、具体的な境界も確認した。[D44.1の論文](https://pmc.ncbi.nlm.nih.gov/articles/PMC2803018/)は酵母表面提示の単鎖抗体を測定しており、その実測を1MLCのFab試料へ付け替えることはできない。変異体と野生型の比を、変異体の独立した絶対測定値として保存しない。現行の必須項目であるロットとイベント日時が原資料にない場合も、測定CSVの経路は完了できない。出版日・取込日時、架空のロット、PDB著者番号とIMGT番号の読み替え、実在しない人の照合記録で補わない。まず、既存の科学ツールの出力と実際の来歴を利用し、対応表の準備の負担を減らす。不明な来歴をより詳しく表す設計が必要なら、別途レビューと承認を経てから変更する。
