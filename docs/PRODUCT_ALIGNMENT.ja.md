# 製品目的との整合確認

[English](PRODUCT_ALIGNMENT.md) · [最上位の目的](../PRODUCT_GOAL.md) · [実行仕様](../DEVELOPMENT_PLAN.md) · [開発状況](PROGRESS.md)

研究者が抗体を観察し、疑問を検討し、根拠を比較し、変異体や実験を設計し、その判断理由を次の担当者へ残せることを目指します。
機能数よりも科学的な正確性、観察の自由度、判断の透明性を優先します。
科学的な判断の主体は研究者です。

重要な開発段階、文脈の要約後、優先順位を変更するときには、次を確認します。

1. 元の製品思想、対象研究者の問い、E/W/D/Rを通る一連の操作、受入条件を読み直します。追加の例や用語の訂正は、明示的な指示がない限り、新機能の優先課題にはしません。
2. 保存された結果を根拠に、研究者が何を観察・理解・判断できるようになったかを説明します。分子、コンストラクト、試料、残基、根拠の対象、条件、不確実性を確認します。
3. 一連の研究行動を妨げる最大の不足を特定します。独立した機能を増やすより、その行動を最後まで成立させることを優先し、より簡潔で有効な方法を検討します。
4. 作業量と研究上の価値が釣り合っているかを見直します。主要な画面の設計前に、関連する既存の科学ソフトウェアを2つ以上比較し、[SCIENTIFIC_UX.md](SCIENTIFIC_UX.md)に参照元と再利用・独自実装の判断を記録します。使い慣れた操作、必要な情報密度、正確な単位と識別子、直接操作、同期した表示を優先し、詳細を段階的に開けるようにします。目的からの逸脱、過度な設計、装飾的なダッシュボード、枝葉の調整、研究に役立たない指標の追求を修正します。同一性、来歴、機密性、回帰検証の条件は守ります。
5. 別担当が技術面と製品目的の両方を確認します。未完成の範囲を明示し、工学試験の合格を科学的な妥当性や実研究者の評価の代わりにしません。

元の対象者、操作経路、科学的定義、データ共有方針、完了条件は変更しません。

## 現在の評価：F12/F13 / J03/J04

今回の成果は、元の情報を観察し、検討した問いを保存するまでの連続した操作です。
構造・計算担当者は対象のモデルを比較し、対応付けた残基や構造上だけの位置を観察し、モデル内部の指標と限界を確認して、変異仮説と次の実験を残せます。
物性評価担当者は測定結果から出典に記載された位置をたどり、配列・構造と実測・計算の原根拠を確認し、新しい子候補と検証したい問いを保存できます。
報告された位置との関連付けだけでは、因果関係や試料全体の測定値が特定の残基に由来することを示しません。
親の実測値と元の記録は変更しません。

現在の工学的な受入はJ01〜J04の4経路と、指定された異常系8件です。
残り4経路、科学的な正解データの人手照合、実研究者の評価、最終品質条件は未達です。
テスト件数や合成の試験例だけで科学的な妥当性や実用性を認定しません。
公開実験構造1MLCは、実際の抗体規模での表示と元データの保持を別途確認するためのものです。
予測信頼度や科学的な正解データの検証とは区別します。

既存のローカルビューアーの表示・視点操作、同一性、番号対応、数値の比較条件、変更不能な記録の保存を再利用しました。
新しい描画エンジン、解析、二次構造の推定、恣意的なスコアは追加していません。
独立レビューで、遅れて返った構造情報から古い候補の仮説画面が開く問題を修正し、公開構造ファイルの元のバイト列も保持できることを確認しました。

一連の操作で残る最大の不足は、J05の対話的な分子構成設計です。
次は既存の構成グラフを使い、鎖・領域・リンカーの順序と元の結合単位IDを明示し、設計比較と未検証事項の記録までを成立させます。
その後、J06のコンストラクト・試料比較、J07の条件を伴う判断の確定と改訂、J08の形式別取込と再現確認へ進みます。
主要な画面ごとに既存の科学ソフトウェアを2つ以上比較し、無関係な予測エンジン、画面全体の置換、枝葉の機能追加を優先しません。
