# 製品目的との整合確認

[English](PRODUCT_ALIGNMENT.md) · [最上位の目的](../PRODUCT_GOAL.md) · [実行仕様](../DEVELOPMENT_PLAN.md) · [開発状況](PROGRESS.md)

研究者が抗体を観察し、疑問を検討し、根拠を比較し、変異体や実験を設計し、その判断理由を次の担当者へ残せることを目指します。
機能数よりも科学的な正確性、観察の自由度、判断の透明性を優先します。
科学的な判断の主体は研究者です。

重要な開発段階、文脈の要約後、優先順位を変更するときには、次を確認します。

1. 元の製品思想、対象研究者の問い、E/W/D/Rを通る一連の操作、受入条件を読み直します。追加の例や用語の訂正は、明示的な指示がない限り、新機能の優先課題にはしません。
2. 保存された結果を根拠に、研究者が何を観察・理解・判断できるようになったかを説明します。分子、コンストラクト、試料、残基、根拠の対象、条件、不確実性を確認します。
3. 一連の研究行動を妨げる最大の不足を特定します。独立した機能を増やすより、その行動を最後まで成立させることを優先し、より簡潔で有効な方法を検討します。
4. 作業量と研究上の価値が釣り合っているかを見直します。主要な画面の設計前に、関連する既存の科学ソフトウェアを2つ以上比較し、[SCIENTIFIC_UX.md](SCIENTIFIC_UX.md)に参照元と再利用・独自実装の判断を記録します。使い慣れた操作、必要な情報密度、正確な単位と識別子、直接操作、同期した表示を優先し、詳細を段階的に開けるようにします。目的からの逸脱、過度な設計、装飾的なダッシュボード、枝葉の調整、研究に役立たない指標の追求を修正します。同一性、来歴、機密性、回帰検証の条件は守ります。
5. 別担当が技術面と製品目的の両方を確認します。未完成の範囲を明示し、工学試験の合格を科学的な妥当性や実研究者の評価の代わりにしません。

元の対象者、操作経路、科学的定義、データ共有方針、完了条件は変更しません。

## 現在の評価：F14/F15 / J05

J05では、元の結合単位を選び、鎖・領域・リンカーの順序とコピー数を明示し、元の鎖と区間の使い方を確認して保存できます。
保存した各鎖の配列と元のIDを観察し、別の設計と比較して、未検証事項と次の実験を残せます。
合成の工学試験用データによる一連の操作を、独立した担当が確認しました。
区間、構成要素ID、宣言した接続、構成変更の親子関係は、再起動・出力・再取込後も保持されます。
同じ配列でも、元の結合単位のIDをまとめません。
不足する相方の鎖や、部分的な区間の使用、コピー数の偏りを明示します。
元の鎖の使用数だけでは、機能する結合単位の数、結合価、実際の会合は保証しません。

現在の工学的な受入はJ01〜J05の5経路と、指定された異常系10件です。
M3の工学的な受入条件には合格しました。
残るJ06〜J08、科学的な正解データの人手照合、実研究者の評価、最終リリース条件は未達です。
テスト件数や合成の試験例だけで科学的な妥当性や実用性を認定しません。
公開実験構造1MLCの表示・保持の検証も、予測精度や科学的な正解データの検証とは区別します。

BenchlingとHELMの既存の操作例を比較し、現在の構成グラフ、ローカルでの一括保存、Wでの観察、Rの仮説を再利用しました。
標準的な順序変更と作業切替の操作を使い、不要な設計フォームを同時に並べません。
独立レビューで、削除した構成要素のIDが再利用されて別の部品が接続される問題と、古い保存エラーが新しい確認画面に影響する問題を修正しました。
機能を増やすことより、元の情報と操作中の入力を正しく保持することを優先しました。

次の大きな不足は、実際のコンストラクト・試料と実験結果を比較につなぐJ06です。
M4ではコンストラクトの違い、測定結果と試料IDの明示的な対応、元の単位・条件、次の比較実験をつなぎます。
続いてJ07の評価項目・重み・欠測の扱いと判断の確定・改訂、J08の形式別取込と再現確認、最終品質検証へ進みます。
既存の同一性、比較条件、保存済み根拠を再利用し、主要な画面ごとに科学ソフトウェアを2つ以上比較します。
無関係な予測エンジン、分子設計の単独機能の追加、枝葉の調整を先行させません。
