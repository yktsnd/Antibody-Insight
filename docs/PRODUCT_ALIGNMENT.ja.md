# 製品目的との整合確認

[English](PRODUCT_ALIGNMENT.md) · [最上位の目的](../PRODUCT_GOAL.md) · [実行仕様](../DEVELOPMENT_PLAN.md) · [開発状況](PROGRESS.md)

研究者が抗体を観察し、疑問を検討し、根拠を比較し、変異体や実験を設計し、その判断理由を次の担当者へ残せることを目指します。
機能数よりも科学的な正確性、観察の自由度、判断の透明性を優先します。
科学的な判断の主体は研究者です。

重要な開発段階、文脈の要約後、優先順位を変更するときには、次を確認します。

1. 元の製品思想、対象研究者の問い、E/W/D/Rを通る一連の操作、受入条件を読み直します。追加の例や用語の訂正は、明示的な指示がない限り、新機能の優先課題にはしません。
2. 保存された結果を根拠に、研究者が何を観察・理解・判断できるようになったかを説明します。分子、コンストラクト、試料、残基、根拠の対象、条件、不確実性を確認します。
3. 一連の研究行動を妨げる最大の不足を特定します。独立した機能を増やすより、その行動を最後まで成立させることを優先し、より簡潔で有効な方法を検討します。
4. 作業量と研究上の価値が釣り合っているかを見直します。主要な画面の設計前に、関連する既存の科学ソフトウェアを2つ以上比較し、[SCIENTIFIC_UX.md](SCIENTIFIC_UX.md)に参照元と再利用・独自実装の判断を記録します。使い慣れた操作、必要な情報密度、正確な単位と識別子、直接操作、同期した表示を優先し、詳細を段階的に開けるようにします。目的からの逸脱、過度な設計、装飾的なダッシュボード、枝葉の調整、研究に役立たない指標の追求を修正します。同一性、来歴、機密性、回帰検証の条件は守ります。
5. 別担当が技術面と製品目的の両方を確認します。未完成の範囲を明示し、工学試験の合格を科学的な妥当性や実研究者の評価の代わりにしません。

元の対象者、操作経路、科学的定義、データ共有方針、完了条件は変更しません。

## 現在の評価：F09 / J01

今回の成果は、合成の工学試験用データであることを明示して検証した、根拠と理由を持つショートリストの操作です。
800候補を取り込み、出典を持つCDR-H3群と結合データの条件を確認し、2候補を比較し、5候補と理由・原根拠を再起動後にも保持できます。
条件の一致は、測定の科学的な比較可能性や生物学的な推奨を意味しません。

製品全体は未完成です。
変異体、研究上の仮説、分子構成の対話的な設計、コンストラクトと実験値の比較、判断の確定と改訂が主な不足です。
残り7経路、科学的な正解データの人手照合、実研究者の評価、最終品質条件も未達です。

次はM3で、親抗体・比較配列から番号付き置換、子候補の差分、根拠と仮説の保存までをつなぎます。
その後、分子構成の設計とM4の実験比較・意思決定へ進みます。
既存の同一性、根拠、番号対応の仕組みを再利用します。
これらの研究行動に具体的な支障がない限り、新しい予測エンジン、自動解釈、クラウド接続、装飾、用語調整を優先しません。
