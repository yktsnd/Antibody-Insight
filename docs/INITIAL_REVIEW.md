## 開発環境

開始時の作業フォルダーはコミットのないGitリポジトリで、既存コードはなかった。
追加提示されたGitHubのyktsnd/Antibody-Insightを接続して確認すると、mainにはApache-2.0のLICENSEのみがあった。
mainを基点にcodex/initial-workspaceブランチを作成した。
以前のantibody-inspectionは再利用の前提にしない。
実行用Python 3.12、SQLite、Node、試験用Playwrightが利用できる。
新規構築が妥当である。

## 不足と解消方法

| 不足または曖昧さ | 解消方法 | 製品目的への変更 |
|---|---|---|
| ファイルの具体的スキーマ、ID衝突時の操作 | バージョン付きJSON、CSV列、FASTA制約を文書化し、プレビュー後の明示保存と原子的取込を採用 | なし |
| 未知の鎖とFASTAからの分子形式推定 | 配列のみの取込はformat=unspecified、role=unknown。IgGやVH/VLを推測しない | なし |
| 実測の分子帰属と試料ID必須の関係 | 実測はMaterialのみを直接対象とし、Constructを経てMoleculeへ参照する。既存ファイルに試料情報がなければ拒否する | 科学的誤帰属を防ぐ具体化。独立レビュー対象 |
| 必須指標欠測時の確定可否 | 確定を拒否し、不足理由を返す。下書きの選定メモは別に保存可能 | なし。J07の制御を厳格に実装 |
| 番号付け、構造対応、変換の実装方法 | 外部検証済み対応表を後続で取り込む。配列インデックスをIMGT番号として扱わない | 最終範囲を削らず未達として追跡 |
| 18固定例の科学的正解と評価者 | 合成の工学試験例と人手照合済みゴールデンデータを区別する。後者は未了 | 完了条件は維持 |
| OSのバックアップ、OneDriveによる同期 | アプリの既定保存はLOCALAPPDATA。作業ツリー、Git、JSON出力には実研究データを自動保存しない | 既定の外部送信なしを維持 |
| 工学KPIとモデル妥当性 | 工学KPIを科学的精度の代用にしない。予測モデルは現段階では実行しない | なし |

依頼者の製品判断が必要となる変更は、現時点では採用していない。
外部送信、科学的意味の変更、利用者または画面の削除が必要になった場合は、別途選択肢を提示する。

これはJ01/J08の一部であり、CDR-H3による群分けや構造表示まで成立したJ01/J03とは報告しない。
