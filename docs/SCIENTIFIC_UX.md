# Scientific UX references and reuse decisions

Recorded 2026-11-03 before designing the M3 interface. This is a comparison of official documentation and documented interactions, not a claim of hands-on usability testing in the desktop applications. Independent workflow replay and researcher evaluation remain separate requirements. No proprietary input was submitted to an external tool.

## Benchmarks

| Established tool / primary reference | Observed interaction | Applicable need / implication |
|---|---|---|
| [Jalview editing](https://www.jalview.org/help/html/editing/index.html) and [annotation associations](https://www.jalview.org/help/html/features/annotationsFormat.html) | Sequence/column selections, edit modes and undo; annotations explicitly associated with sequences or groups; alignment-column and sequence numbering are distinct | E/W/D, P01/P02/P04: compact sequence rows, explicit selected residues, source-linked region annotations and a reference comparison; do not present raw offsets as aligned coordinates |
| [IMGT/V-QUEST interface](https://www.imgt.org/IMGT_vquest/input) and [IMGT numbering](https://www.imgt.org/IMGTScientificChart/Numbering/IMGTnumbering.html) | Detailed versus synthesis results, numbered protein displays, changes-only display, mutation/AA-change tables, tool/reference versions and downloadable tabular results | E/D, P01/P02: show chain, scheme, insertion and FR/CDR alongside original and proposed residue; use a compact mutation table with full sources available; never infer a missing numbering result |
| [Mol* selections](https://molstar.org/viewer-docs/making-selections/) and [navigation](https://molstar.org/viewer-docs/maneuvering-in-mol_/) | Explicit picking level, selection through either 3D or sequence panel, focus on selection and operations on selected components | W, P02/P03/P04/P05: maintain reciprocal selection, actual model/chain/residue identities and familiar camera controls; distinguish focus from changing a scientific selection |
| [Jalview sequence features](https://www.jalview.org/help/html/features/seqfeatures.html), [feature format](https://www.jalview.org/help/html/features/featuresFormat.html) and [tutorial](https://www.jalview.org/help/documentation/TheJalviewTutorial-screen.pdf) | Features belong to particular sequences, with position-linked detail and selection-based feature creation | W/R, P02/P03/P04: attach a concern or hypothesis to the actual candidate/residue; expose source detail from the selected position. The independent reviewer corroborated the HTML sources because the PDF fetch timed out |
| [eLabFTW experiments](https://doc.elabftw.net/docs/usage/user-guide/experiments/) and [traceability](https://doc.elabftw.net/docs/usage/traceability-and-auditability/) | Familiar entries with identity, status, text, linked resources/experiments, steps and export; distinct viewing/editing and history controls | R, all personas: retain a plain research question and next experiment with linked original evidence; use explicit proposed status and immutable saved records, not an opaque AI judgment |

Jalview and IMGT establish E/D references; Mol* and Jalview establish W references; eLabFTW and Jalview establish R references. ChimeraX Rotamers/Sequence Viewer official pages were attempted but could not be fetched in this environment; they are not counted as a completed benchmark and no behavior is assumed from them.

Scientific constraint from IMGT: shared numbering supports coordinate comparisons, but the documented CDR comparison statement is qualified by equal CDR length. The planned reference display is an exact **recorded-coordinate comparison**, not inferred alignment or homology. Unequal observed region lengths and absent coordinates must stay explicit. A reference does not authorize transferring an annotation or structural confidence to a child.

## Reuse versus build

| Major interface | Reuse first | Documented unmet need / justified custom part |
|---|---|---|
| E candidate exploration | Native selectable/sortable data table and established summary-versus-detail pattern | Preserve separate molecule/material/source IDs while choosing a condition-specific observation and retaining a cross-screen selection. The requester explicitly disallows generic dashboards. The large statistic cards have been replaced by one compact count line adjacent to the table, retaining the same actual counts/IDs and regression coverage. No dashboard expansion |
| W sequence/structure observation | Existing pinned local 3Dmol component, Gemmi source parser and existing reciprocal-selection adapter; Mol*/Jalview interaction patterns | Explicit imported IMGT/raw/structural identities, missing correspondences and chosen conformers must remain inspectable. Retain the licensed local viewer instead of replacing it for novelty. Benchmark identified future usability checks: molecular representation clarity on real antibody-scale input, dense sequence comparison and selected-residue navigation. Resolve demonstrated issues before full J03 acceptance |
| D substitutions/comparison | Existing numbering observations, HTML table/form controls, exact-source region labels; Jalview/IMGT row/column/reference patterns | An immutable child + coordinate-bearing lineage tied to local Materials/Evidence is not supplied by an embedded generic sequence editor. Build a narrow substitution table: parent map/reference → observed coordinate/region/AA → requested change → actual before/after preview. Keep the parent untouched; no in-place alignment editing or automated humanization |
| R hypotheses/decisions | Existing evidence rows/source drill-down, native text fields/checklists, eLabFTW entry/link pattern | Persist a distinct proposed Hypothesis with exact molecule/evidence/lineage/model/residue scope, alongside original evidence and immutable decisions. A generic notebook cannot enforce these existing domain identities without integration. Reuse the current preview/atomic-import mechanism; do not add a separate notebook/editor framework |

No Jalview, IMGT, Mol* or eLabFTW code, assets or styling is copied. They are UX references. Existing third-party runtime licensing remains recorded in THIRD_PARTY_NOTICES.md. Before embedding another component, inspect its current license, local/offline behavior, source availability and maintenance implications; pattern familiarity is not authorization to copy code or enable external services.

## M3 interface and verification plan

- D: parent and explicit source map selector; optional reference map; dense coordinate table with parent/reference AA, region and target AA; direct action from the selected W residue; removable staged changes and one before/after preview. Show absent reference coordinates and source/verification states. Never preselect a different map to make an operation succeed.
- R: plain hypothesis/next-experiment text, recorded limitations, exact related records, preview and explicit save. Keep proposed hypotheses visually and semantically distinct from measured/computed observations. Source detail remains reachable, not replaced by summary scores.
- Independently replay keyboard/mouse selection, insertion identities, parent/child comparison, source drill-down, hypothesis save and restart. Check error recovery and unnecessary steps. The completed J01 must still work.
- Evaluate usefulness through the actual research action, not appearance or control count. Current design is provisional until independent review; real researcher evaluation remains open.

M3 usability iteration: the R hypothesis action is available before long evidence lists; D exposes actual observed CDR counts and source coverage compactly alongside exact-coordinate comparison, with no deletion inference. A missing coordinate produces an explicit unavailable message. These changes support the existing research action rather than adding a separate feature.
