# ADR-0009 Constructs, materials and source-bearing measurement import

- Status: independent design PASS in TEST_EVIDENCE/M4-constructs-design-independent-review.md. Implementation/full J06 and related J08 verification remain pending; M3's registered five journeys are preserved.
- Trace: F16 P06/P08, J06/J08, AC-J06/AC-J08 (measurement CSV and actual Material mapping); F17 P06/P08, J06/J08, AC-J06/AC-J08 (explicit Construct/Material registration); F18 P06, J06, AC-J06 (construct and experiment comparison). These are required missing research actions, not discretionary model/catalog expansion.
- Research question/action: E opens one actual antibody → D compares two Construct IDs, recorded CDS/vector/signal differences → W follows their actual Materials → R inspects expression/quality observations with original units/conditions → R saves the proposed explanation, limitations and next controlled experiment. No expression prediction or causality is generated.
- Benchmark/reuse: verified primary references for Benchling Registry/results, Skyline Document Grid and FASTA two-input comparison were recorded in SCIENTIFIC_UX.md before the interface. CUBA is supplementary and was not counted as a verified required benchmark. Reuse native source/condition tables, existing exact context predicates, atomic preview/import, W subject paths and R hypotheses. Add no alignment engine, statistical pooling, arbitrary score, dashboard, external service or new runtime.
- F16 input: UTF-8 canonical measurement CSV with required `material_ref,metric,value,unit,timestamp`; optional `conditions_json,description` and a paired `source_name,source_version` header set. Each measured row targets an actual same-project Material. An exact known application Material ID may resolve directly; other file tokens require explicit file-scoped mapping to a Material ID. Names, lots, equal sequences, Construct IDs and Molecule IDs never substitute for a Material. Mapping choices show the real Material/Construct/Molecule path. Stale or unused mapping keys reject; source mapping stays in memory until reviewed records are saved.
- Reserved application identity boundary: a canonical typed application ID is not a remappable external alias. A known same-project Material resolves only to itself; wrong-type IDs and unavailable/foreign Material IDs reject rather than being redirected to a different sample. Only genuinely external/unrecognized reference tokens receive explicit mapping. No UUID, case or whitespace normalization establishes identity.
- F16 scientific values: empty value is registered null, explicit zero stays zero, finite numeric syntax uses decimal-point notation and the existing safe-number/underflow limits. Non-null values require an explicit unit; no implicit dimensionless unit, conversion or locale guessing. Empty conditions are unknown/null; supplied conditions must be a JSON object or null and preserve JSON types. A timestamp must be the supplied actual event time, not import time. Missing actual time is an excluded/error row, not an invented date.
- Numeric transport prerequisite (F05/F09, AC-J06/AC-J08): independent browser reproduction found that parsed JavaScript bundles changed integral floats/signed zero and merged exact contexts. Preserve the server-approved serialized awx/1 snapshot for unchanged import/export, with a client fingerprint that rejects edited approved snapshots and requires a new preview. Plain direct import remains strictly server-validated. Nested preview envelopes carry an explicit serialized bundle; never recursively interpret arbitrary user fields. No custom number parser, server cache, localStorage scientific payload or numerical reclassification is introduced.
- F16 source/provenance: per-row source headers, when present, supply a nonempty name and nullable version as a pair; otherwise an explicit file-level source is used, defaulting only to the actual input file name and unknown version. Do not combine a row's source name with an unrelated file-level version. Unknown version remains null. Source notes stay raw description. Optional Evidence `import_origin` records actual file name, SHA-256 of the UTF-8 text submitted to the parser, logical data-record index, physical end-line number and the original exact `material_ref`. This metadata is separate from assay conditions and source tool name, so row provenance does not manufacture a new comparison context. The hash is not a claim about arbitrary original byte encodings. Existing Evidence without this optional field remains unchanged.
- Recorded import provenance also names the actual importer/application version separately from experimental source/version. CSV import computes its submitted-text hash; an imported JSON provenance object is a recorded attestation, not authenticated verification of an absent original file. Qualified/censored strings such as `<0.1`, `>100` and `ND` are not supported point values and must not become zero or threshold point estimates. They reject as numeric values; deliberate curation can retain the original qualification in description with an explicit null scalar. Matching rows/hashes never establish independent biological replicates.
- F16 QC/output: preview counts valid/excluded rows with exact reasons, unresolved sample refs, unsupported fields and source/mapping details. Unknown headers reject with a complete list rather than being discarded. An explicitly reviewed valid subset may be saved through the existing atomic import; saving revalidates every reference. Equal values or equal file hashes are not identity and never automatically merge observations. Potential repeat source rows may be warned about without treating them as new independent replicates or aggregating them. Source row/record identity and actual IDs remain inspectable in R and JSON roundtrip. Strict UTF-8 file decoding rejects unsupported encoding rather than replacing characters silently.
- F17 registration: a researcher can explicitly preview/register a Construct for an actual Molecule, then a Material for an actual Construct. Names, recorded uppercase ACGTN CDS or null, vector/signal metadata or null, and actual Material lot are supplied explicitly; no chain/CDS pairing, translated protein or missing lot is inferred. Add optional actual `source` to Construct/Material for new local researcher metadata entries; it records the entry mechanism/application version, not an authenticated person or inherited molecular/experimental source. Legacy records without it remain unchanged. Registration creates new IDs and no measurements. Existing strict graph/append-only rules apply.
- F18 comparison: choose one actual Molecule context and two of its explicit Construct IDs, not two equal-sequence guesses. Show the actual IDs, recorded source, CDS/vector/signal differences, null/unknown states and raw DNA positions separately from amino-acid indexes. Raw positional comparison is unaligned; no homology, synonymy, strand, signal processing or CDS→protein translation validity is inferred. The Molecule association is declared, including for multichain molecules; no unspecified chain/CDS correspondence is invented.
- If either recorded CDS is null, including two nulls, the CDS comparison is unavailable rather than identical. Local metadata source identifies the actual entry mechanism only; it never authenticates the author or proves the declared CDS codes for the associated molecule/chain.
- F18 Materials/evidence: inspect each real Material/lot and its Construct path. Reuse existing measured/computed/source/unit/assay-context distinctions for a per-observation table; repeated observations and different Materials remain separate rows. Missing conditions/units/version cannot silently join a known context. No means or conversions are produced. Keep every original result available even when it cannot establish an ordering/comparison context. Link the exact original Evidence and subject in R/W. Save the next controlled comparison as an existing proposed Hypothesis with actual related Evidence/subject paths and recorded limitations.
- UI/privacy: extend the existing E import and D task patterns, with progressive source/detail disclosure. Keep molecular/construct/material/Evidence selections as actual IDs across E/W/D/R. Mapping tokens, CSV text, sequences and draft notes stay out of localStorage. Preview/save/error callbacks must retain original project/draft/selection ownership. No runtime network access or confidentiality-policy change.
- Required main test: same declared protein/Molecule, two independently identified Constructs with different CDS/signal metadata, three Materials and expression/quality observations → explicit source mapping/CSV QC → actual Construct comparison → W subject paths → R units/conditions and next experiment → real restart/export/fresh reimport with exact IDs/values/source/provenance and unchanged originals.
- Required negatives: unknown/unmapped Material reference never attaches measured data to the Molecule or another sample; different units/unknown conditions are not averaged or pooled. Additional boundaries: same labels across Constructs, explicit null versus zero, repeated observations, malformed CSV/duplicate headers/unknown columns, hostile text, unsafe numbers/underflow, wrong/foreign mapping IDs, source-version mixing, stale file/target/preview/save, legacy optional-field absence and immutable snapshots.
- Non-goals/gates: J07 finalized criteria/revisions and full J08 prediction adapters follow separately. No ELN/LIMS replacement, biological translation/expressibility claim, automatic assay normalization or model execution. Independent design PASS before implementation; independent API/scientific/UX/full J06 and retained J01–J05 verification before registration. Scientific golden/reference and actual researcher evaluations remain open.
