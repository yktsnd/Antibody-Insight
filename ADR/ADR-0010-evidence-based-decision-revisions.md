The original charter/specification authorizes this required research action; no mission or sharing-policy change is introduced.

- Research action: E selects three actual candidates → R compares original binding/property/expression observations by explicit criterion/source/condition → W inspects an important original subject/source → R records criteria, declared weights, trade-offs and selected candidates → R reviews and saves a finalized immutable record, exports it, and later creates a separately identified revision.

## Proposed bounded contract

1. Preserve all existing awx/1 Decision records and shortlist behavior exactly. Existing `criteria: []`, `status: draft`, revision1 without supersedes remains a valid legacy shortlist. Do not rewrite old records or reinterpret them as finalized decisions.
2. A researcher-defined criterion records a stable local criterion key, readable name, declared nonnegative finite weight, `required` boolean and explicit preference (`higher`, `lower`, or `inspect`). Weight is a researcher's declared importance, not a model probability or validated biological score. No normalization, total score or automated candidate ranking is calculated. Preference is an interpretation aid, not a scientifically inferred optimization objective.
3. Each numeric criterion names an actual original Evidence context anchor. Derive kind, metric, unit, typed conditions and source/version using the existing exact F09 predicates; do not let arbitrary client labels manufacture a new compatible context. The original anchor remains in the frozen Evidence snapshot even when it is not the selected observation for a candidate.
4. Every candidate has an explicit selected original Evidence ID or null for each criterion. Resolve the original subject through actual Material/Construct/Molecule/Structure paths using current domain rules. No equal-sequence or label matching, automatic first/latest choice, averaging or replicate claim. When multiple observations exist, the user must choose one actual source record. Null/missing scalar, unknown/incompatible context and unavailable observations remain explicit. Measured and computed criteria never silently share a context. Literature/annotation and other original evidence remain inspectable in the evidence cards; they are not silently coerced into numeric criterion values.
5. The review table shows exact original values/units, missingness, original subject/lot, source/time/conditions and declared weights/preferences. A required criterion with missing numeric observation for any comparison candidate blocks finalization; it never becomes zero. To proceed with a different research question, explicitly revise the requirement and explain the change. Drafts can retain missing/ambiguous observations and identify unresolved work. Matching metadata alone does not establish biological comparability.
6. New criterion-bearing decisions record both the actual comparison `candidate_ids` and an explicit subset of chosen candidate IDs (may be empty only in drafts), reason/trade-offs and actual local-entry source/application version. Keep new fields optional for legacy records, but require them for finalized criterion-bearing decisions. A nonempty criterion set, nonempty actual chosen IDs, complete required observations, valid source snapshots and nonempty reason are finalization gates. No fabricated total score or confidence field is permitted.
7. Every saved decision version, including drafts, is append-only. A revision references the actual same-project previous Decision via `supersedes` and has exactly previous revision+1. A first version has revision1 and no supersedes. A previously finalized record is never changed; a later update creates a new ID and explicit successor. Prevent cycles, wrong-type/foreign predecessors and concurrent/stale successor forks atomically. Old snapshots remain unchanged when later Evidence is added. Revisions may explicitly change candidate scope, choices, criteria and weights; before/after differences are visible from the actual version chain.
8. Save complete original Evidence snapshots for anchors, criterion observations and any additionally selected supporting records. All selected observations and anchors must belong to the actual comparison candidate scope. Snapshot validation retains the current strict canonical equality to original Evidence, including numeric types and signed zero. Optional `hypothesis_ids` reference existing immutable proposed Hypotheses whose entire Molecule scope is within the comparison; their related Evidence is included in the frozen evidence union. Preserve those actual IDs through export/reimport. Reuse current hypothesis scope checks and source cards; introduce no second hypothesis editor, status promotion or mutable narrative.
9. The server derives/revalidates the criterion table and finalization blockers for preview, then validates all saved records again within the existing atomic append-only import. Client-supplied readiness, scores or fabricated contexts reject. Local entry provenance identifies the actual application mechanism, not authenticated human authorship. Existing local session/Origin/CSRF, no external transmission and volatile scientific draft rules remain unchanged.
10. R uses progressive criterion/detail disclosure and the existing original evidence cards. Following an original record to W preserves actual candidate, criterion/decision IDs and source context; returning to R preserves the unsaved decision draft in memory. Draft notes, criteria source content and scientific values never enter localStorage. Async preview/save/rejection is bound to actual project, selection, decision revision and draft owner. Export includes exact IDs, full frozen evidence/criteria/weights, reason, timestamps, status and revision history through the existing fresh awx/1 export.

## Clarified validation boundary for independent review

- New stored Decision fields are `chosen_candidate_ids`, `source`, and `hypothesis_ids`. Legacy means ALL three are absent AND the exact old contract holds (`criteria: []`, `status: draft`, `revision: 1`, `supersedes: null`). Any new-field presence or nonempty criterion set enters the new contract and requires ALL three new fields; partial/truncated shapes cannot use the legacy gate. Source is the actual local-entry mechanism/application version for generated records, and recorded source metadata for imported records, never authenticated authorship.
- New drafts may have `criteria: []` and `chosen_candidate_ids: []` to retain an unresolved comparison with a nonempty reason. Finalized decisions require at least one fully defined criterion and at least one chosen candidate. Every new draft criterion still has a stable key, nonempty name, explicit safe nonnegative numerical weight, `required` boolean, explicit preference, eligible original anchor and total candidate-keyed choices. Incomplete weights, preferences, anchors or reference shapes reject; a draft's supported incompleteness is missing criteria, unchosen candidate, null choice or missing scalar, not malformed scientific metadata. No empty input is silently converted to zero.
- Legacy shortlists may be superseded by a new-contract version with the same existing revision rule (new revision2 points to the actual legacy revision1). The old record is preserved exactly; it is not upgraded or edited. A new revision can explicitly alter comparison scope. All successors, draft or final, participate in the same one-successor-per-predecessor atomic constraint. Multiple independent first-version decisions remain possible.
- Each criterion anchor must be an actual scoped Evidence with `context_issue(anchor) is None`, even for a saved draft. Reuse `context_issue/context_key`; do not inherit `observation_order`'s automatic sole-observation selection. A non-null choice must be actual, belong to that exact candidate and have the exact eligible context. Total `evidence_choices` keys equal the comparison candidate set; values are an actual eligible Evidence ID or null. A selected original Evidence whose scalar is null remains selected and is reported value-missing. Null choice remains explicit even when exactly one eligible record exists; when several exist, report choose-observation without selecting first/latest. Incompatible or stale IDs reject rather than becoming missing cells.
- Required means a complete selected numeric observation for EVERY compared candidate, including unchosen candidates. This is a conservative, explicit readiness policy for this slice, not a claim about scientific validity. Changing the requirement or comparison scope requires explicit researcher action/reason in a saved version and visible version differences; there is no automatic waiver or recommendation. Optional missing observations remain visible in finalized records.
- Criterion presence, weight and preference changes are recorded between saved immutable versions. Unsaved edits remain a volatile draft; the product does not claim an authenticated keystroke/audit history. The original strict Evidence snapshot equality, source context and predecessor checks are enforced again for direct JSON import as well as UI preview/save. Server preview must show blockers; a finalization request with any blocker rejects atomically.

## Tests and gates before implementation

- Main: three actual candidates with original binding/property/expression observations; some missing optional values; explicitly select repeated observations; edit and save criteria/weights, inspect a source in W and return without losing draft, review/finalize an explicit choice, export/restart/fresh reimport exact frozen records; revise a finalized decision and retain both exact versions.
- Prescribed negative1: missing/null numeric observation for a required criterion blocks finalized save atomically; draft remains possible, no zero substitution. Explicitly revising requirement is recorded as a new saved version.
- Prescribed negative2: later Evidence does not change the existing final record or its snapshot; stale/concurrent revision cannot overwrite or silently fork it.
- Additional edges: source/units/typed-condition/kind mismatch; ambiguous observations; unrelated or equal-sequence candidate; wrong/foreign/duplicate IDs; empty chosen subset; unsupported score/context fields; forged snapshot or predecessor; immutable legacy drafts; signed-zero/integral-float roundtrip; zero/negative/nonfinite weights; stale project/selection/preview/save; safe rendering of source text; no proprietary data in localStorage or network requests.
- Mandatory gates: actual identity/provenance/security/regression and independent design/implementation PASS. Follow original P07 J07 AC exactly; no plan/mission/data-sharing change. Existing J01–J06 and their negatives must remain coherent. Human scientific golden and researcher evaluations remain separate open requirements.
- Return path: unintegrated code can be reverted without mutating existing append-only project data. No production research database is used by tests.

## Alternatives, decision owner and reconsideration

An automatic desirability/composite ranking would require scientifically defensible scaling and model assumptions and is unnecessary for recording the researcher's judgment; it is excluded from this slice. A separate decision database/screen or generic workflow engine would duplicate existing IDs, snapshots and R. Reuse the current entities and explicit version references instead. Silent mutable decisions violate AC-J07.
