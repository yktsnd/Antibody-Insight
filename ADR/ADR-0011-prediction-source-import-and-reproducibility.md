## Alternatives and proposed scope

A canonical scalar-only JSON is simple but leaves researchers converting common tool outputs themselves. Parsing every model's arrays/coordinate semantics would require unsupported scientific assumptions and excessive work. Proposed middle path: support a strict canonical computed-evidence JSON plus an explicitly selected native AlphaFold 3 summary scalar adapter; retain the entire original JSON once, list unsupported/unmapped content and preserve it through export. Detailed atom/token/pair-array interpretation remains unsupported, without flattening, averaging or inventing residue correspondence.

The native adapter handles documented `ptm`, `iptm`, `fraction_disordered` and `ranking_score` scalars, including explicit null. The official definition supplies their dimensionless units and applicable ranges; reject booleans, nonfinite/unsafe values or out-of-range points. Do not generate a scalar for an absent field. Other content, including boolean/chain/array fields, is retained in original JSON and explicitly listed as unmapped. A summary with no supported scalar does not create fake computed results. Ranking is a source model's structure-ranking output, not measured binding or this application's recommendation. These are imported source values, not a model executed here.

Primary definition: [official AlphaFold 3 output documentation](https://github.com/google-deepmind/alphafold3/blob/main/docs/output.md), verified2026-11-04. Native metric interpretation is bounded to that documented format, not inferred from filenames or arbitrary metric names. No model code, weights or other tool assets are copied; source attestation does not authenticate an external run.

## Original source record and scientific boundaries

1. Add a narrowly scoped immutable `prediction_file` entity (typed `prf_` UUID) to store original UTF-8 JSON text, submitted-text SHA-256, actual input filename, explicit file format, exact subject bindings, format-specific import options and actual importer/application version. Creation time records import activity; it is separate from the original computation event time. No original entity or provenance field is reinterpreted. Existing records without the new type/ref remain unchanged; older apps may reject unfamiliar fields/types rather than discard them.
2. New optional Evidence `prediction_origin` references the actual prediction_file ID and exact JSON pointer for its original value. Only computed Evidence may use it. Whole-project validation re-derives the corresponding source record/value/context and exact subject mapping, checks typed scalar equality and rejects inconsistent or forged references. Imported provenance remains recorded attestation, not authentication of a missing original model run. Store raw source only once, rather than duplicating a large file on every scalar.
3. Canonical format `computed-evidence/1` has root schema_version and records. Every record explicitly supplies kind=`computed`, subject_ref, metric, value, unit, source{name,version}, timezone-bearing timestamp and conditions; optional description/residue_refs retain source scope. Scalar values are finite safe JSON numbers or null; non-null values need an explicit original unit. No default model score, tool version, time, confidence, unit conversion or qualifier-to-point conversion. Arbitrary typed parameter metadata in conditions is retained without being interpreted as a scientific definition.
4. Canonical references resolve exact known same-project Molecule/Construct/Material/Structure IDs, preserving their distinct types. Opaque external tokens require file-scoped explicit mappings to actual subjects, with the complete actual type/path visible. Canonical typed application IDs are reserved and cannot be redirected; wrong-type/unavailable/foreign IDs reject. No case/whitespace/UUID, name, lot or equal-sequence matching. Nonempty external mappings bind to this exact submitted-text digest; unused/stale mappings reject.
5. Native summary import explicitly selects an already registered **computed** Structure and an actual known positive source-model ID from that file. There is no default model1, top-sample selection, experimental-structure confidence attachment or sequence/residue mapping inference. Require an actual source event timestamp and recorded tool version or explicit unknown/null; user-provided computation conditions stay separate from importer metadata. If a supplied structure_model conflicts with the selected actual model, reject rather than overwrite it. File/sample/run identifiers are recorded only when actually supplied, never guessed from a filename. Preserve original metric names and label model-internal metrics, including ranking, with their scientific scope.
6. Canonical invalid records get explicit row/pointer QC and may be excluded from a reviewed valid subset; unknown schema fields are listed completely and reject rather than being dropped. Native unmapped fields are preserved in the original content and listed explicitly, not converted into scalar Evidence. Malformed/duplicate-key/unsafe numeric JSON and unsupported encoding reject without writes. Parsing may ignore one leading UTF-8 BOM while preserving the exact submitted text/hash; no replacement decoding. Empty/fully invalid imports do not enable a misleading source-only save. Review makes source-file entity count distinct from computed-value count.
7. Raw content, hash, bindings/options and original scalar origin survive native full-project export/reimport. Source pointers use original JSON record/field identity, not invented physical line numbers. Source entity shape/references and computed origin consistency are validated again on direct awx/1 import, not only adapter preview. Limit total input/storage to existing request/entity ceilings and explicitly reject oversized records; never truncate arrays or scientific content to fit.

## Interface, security and compatibility

Implementation interpretations required by the independent review: collect every canonical unknown schema-field pointer before rejecting the entire file; only known-schema row errors permit a valid subset. A native summary is one record and any malformed recognized scalar rejects that summary. A coordinate-model ID is not an external sample/run ID, and the file association is user attestation rather than authenticated matching. Parse once per validation where practical. Bound the complete JSON-escaped project as well as the individual input, so every accepted project can be reimported within the existing32MiB request ceiling. Existing FASTA/CSV provenance is replayed as actually stored; do not claim raw files that earlier adapters never retained.

The source entity also records a unique allocation list of exact source-value JSON pointers to generated Evidence IDs. Its computed origins must agree with that allocation in both directions. This preserves distinct identical rows and detects changing an Evidence pointer to another equal-looking source value; the allocation records importer associations, not authenticated external row identity or a causal dependency. Unknown/omitted/duplicate allocation dependencies reject. A completely changed imported source and its matching metadata remain recorded attestation, not cryptographic proof of an external run. The complete-project transport-size gate applies to atomic import and legacy shortlist saves, with no truncation or mutation of already stored records.

Extend E's format chooser and reviewed preview. Canonical JSON uses explicit subject mappings; native summary uses actual Structure/model selectors and source time/version/conditions. Keep raw content, mapping tokens and scientific drafts in volatile memory. Preview/save/error/file decoding stays bound to actual file/project/options/draft ownership. Registered data remains append-only, and a failed preview/save must leave other records unchanged.

W/R can open the actual original prediction_file, filename/hash/importer, recorded subject/model and preserved raw JSON from the Evidence origin. Distinguish extracted scalars from retained but uninterpreted fields. Unknown source version/context is visible; it does not silently join an eligible F09 context. W confidence uses only the exact source file/model; no confidence is invented from coordinates/B values or a neighboring sample. No chain/atom/token arrays are relabelled as whole-molecule values.

Existing awx/1 export already includes complete entities and dependencies; extend strict validation rather than add a second archive, generic ETL engine, object store or private-data service. Native full-array interpretation, every external model's custom format, AIRR expansion and running/reproducing a model computation are not claimed by this import slice. J08 demonstrates faithful dataset/provenance reconstruction, not computational or biological equivalence of an unexecuted model. Track any remaining final-goal gap explicitly.
