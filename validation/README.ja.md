# 科学的な正解データと研究者による評価

[English](README.md) · [受入仕様](../DEVELOPMENT_PLAN.md)

自動試験では、記録の復元と画面操作を検証します。
注釈の科学的な正しさや、実際の研究での有用性を確かめる人の評価は、別途必要です。
以下の条件が満たされるまで、Release1.0を完成と認定しません。
評価者や評価結果を仮に記入することはありません。

起動中のアプリは http://127.0.0.1:8765 で開けます。起動していない場合はstart.ps1を実行します。
評価時の実際の版・コミットと、入力資料のハッシュ値を記録します。
機密の配列・実験データは外部サービスへ送らず、既存の研究データを上書きしないよう、評価専用の別の保存領域でローカルの入力コピーを使います。

評価用の別領域を使う場合は、プロジェクトのフォルダーでPowerShellを開き、未使用のデータベース名を指定して起動できます。

```powershell
.\start.ps1 -Database "$env:LOCALAPPDATA\AntibodyInsight\human-evaluation.sqlite3" -Port 8766
```

この評価用セッションは http://127.0.0.1:8766 で開きます。既存のファイル名を指定すると、その記録を開きます。新しい評価には別のファイル名を使ってください。

## 18種類の固定例を人が照合する

SCIENTIFIC_GOLDENS.csvに、開発計画書10.1節の18区分を用意しています。
実際の入力、独立して確認した期待値、一次資料・方法とバージョン、評価者、評価日が必要です。
区分の名前や合成の工学試験例だけでは、科学的な正解データとして扱いません。
未確認の欄は空欄のままにし、0や架空の評価日で埋めません。

分子・コンストラクト・試料のID、鎖の宣言、該当する番号付け方式・ドメイン・CDR定義、構造モデル・残基・挿入コード・別配座、根拠の種類・単位・条件・出典と版・日時を、元資料と照合します。
拒否すべき入力や欠測の期待される挙動も確認します。
入力のハッシュ値、期待値のファイル、評価者、評価日、PASS・FAIL・NEEDS-EVIDENCEの判定を記録し、資料と期待値をローカルに保持してください。
人が確認した注釈のみ、その確認を受けたものとして登録します。
既存の合成例を、人が科学的に検証した例へ名前だけで変更しないでください。

公開の実験構造1MLCは、構造読み取り・表示の規模を確認するために保存しています。
その自動試験は18種類の人手照合や予測の妥当性評価の代わりにはなりません。
ヒト抗体らしさのスコア、予測精度、分子の実際の会合、発現への因果的な影響を検証したとは扱いません。

## 元の8役割ごとに研究操作を評価する

RESEARCHER_EVALUATION.csvに、8人それぞれの研究上の問いと操作課題を示しています。
同じ人が複数の役割を担当しても構いませんが、課題ごとに実行し、評価者を記録します。
実際のローカル入力を使って観察・比較・解釈し、次の研究行動と判断理由を保存してください。
達成の有無、誤操作、迷った箇所、未解決の判断、研究に役立つかを記録します。
自動試験の件数でこの評価を代替しません。
8役割分のレビューは初期評価であり、統計的な有効性を示すものではありません。

利用ガイドの言語切替で、英語と日本語の説明も確認できます。
元の値・出典テキスト・指標名・IDは翻訳しません。
humanizationはヒト化、humannessは方法ごとの定義を伴うヒト抗体らしさとして区別します。
現時点でヒト抗体らしさを計算する機能はありません。

記入した評価表と、入力・期待値のローカルの所在を共有いただければ、修正と回帰検証へつなげます。
評価者や適切な入力が不足する項目は未検証として残します。
製品目的・同一性・科学的定義・共有方針に関わる変更は、AGENTS.mdで定めた依頼者の判断が必要です。
